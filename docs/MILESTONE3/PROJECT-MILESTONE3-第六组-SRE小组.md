### 1.3 术语

| 术语 | 定义 |
|---|---|
| Memory | 从原始对话抽取的结构化事实或事件，携带时间及来源 |
| 候选记忆 | 根据问题从指定对话的完整记忆集合自动召回的记忆 |
| 有效记忆 | 在给定问题和时间条件下，可用于支持答案的记忆 |
| RETAIN | 比较范围内事实兼容，相关记忆仍予保留 |
| UPDATE | 同一实体、属性或过程的阶段演化，新阶段更新当前状态 |
| SUPERSEDE | 同一查询语义下，新事实替代旧事实所代表的状态 |
| CONFLICT | 同一时间条件下事实不兼容，现有证据不足以消解 |
| dev / test | 开发调试集 / 独立最终测试集 |
| gold | 仅供评测使用的参考答案、证据或关系标注 |

## 2. 系统概述与范围

### 2.1 问题与目标

计划、职业和偏好随对话变化，仅按相关性检索可能采用陈旧状态。系统须检索记忆、判断关系、解析有效状态，并支持证据回溯。

处理流程：

`LoCoMo 导入 → 结构化记忆构建 → 持久化 / JSON 导出 → 问题与时间条件 → 候选检索 → 关系判断 → 有效记忆解析 → 回答及证据展示`

### 2.2 用户与外部依赖

| 参与者 | 任务 |
|---|---|
| 研究者 / 演示用户 | 选择对话、浏览记忆、提出问题、检查答案与证据 |
| 开发 / 数据人员 | 导入数据、构建记忆、配置模型、排查失败 |
| 测试 / 评测人员 | 执行测试、比较基线、导出结果和复现实验 |
| 外部模型服务或本地预训练模型 | 提供可配置的抽取、嵌入、关系判定或生成能力 |

交付本地单用户 Web 应用，批量构建和评测可用命令行；不要求账号、多租户或公网部署，不训练大模型，不扩展为通用聊天系统。

### 2.3 范围与交付

必做：课程指定 6 段 LoCoMo（4 dev + 2 test）、自动结构化记忆构建、统一 JSON、Web 记忆和证据展示、自动检索、动态关系与有效性解析、基于有效证据回答、三项指标及两类基线。

须标记基础冲突并保留证据。复杂冲突消解、Graph Memory、多跳、压缩、自适应检索和复杂时间推理为 Bonus，不作为核心验收前提；调整 M2“完成所有 Bonus”的承诺须评审。

M3 交付本文；M4 交付必做链路、设计、源代码、Web、示例 JSON、测试记录和中期展示，评测工具须可运行；M5 完成独立测试、对照分析、最终报告与展示。

## 3. 数据需求

### 3.1 数据集与隔离

- 课程选定 6 段，conversation ID、划分和标注版本待确认。
- 清单记录来源、版本或文件摘要、conversation ID、split、导入时间。
- dev 用于调试；test 按冻结流水线构建 Memory，其答案和动态标注不得用于调参。
- 抽取、索引和回答仅用原始对话及允许的时间上下文；gold 答案、证据列表和事件摘要不得进入推理。事件摘要仅供隔离的离线核查。
- 标识在命名空间内唯一；证据以 `(conversation_id, session_id, turn_id)` 联合定位，禁止跨对话混用。

### 3.2 逻辑数据契约

以下约束导出和查询结果，不限定物理存储。

| 对象 | 字段与约束 |
|---|---|
| Conversation | `conversation_id`、`split`、`dataset_version`、sessions |
| Session | `session_id`、原始时间字符串、可解析的标准时间或 null、turns |
| Turn | `turn_id`、`speaker`、`text`，内容保留原始值 |
| Memory | `memory_id`、`conversation_id`、`content`、`entity`、`attribute`、`value`、`session_time`、`time_expression`、`event_time`、`sources`、`record_status` |
| Relation | `relation_id`、`query_id`、`from_memory_id`、`to_memory_id`、`type`、`reason`、`evidence_memory_ids` |
| QueryResult | `query_id`、问题、对话 ID、时间条件、实际截止时间、候选及分数、关系、逐条有效性、有效 ID、冲突 ID、答案、引用、状态、运行配置 |

Memory 必填 ID、对话 ID、content、sources、record_status，content/sources 非空。entity/attribute/value 可空，不得猜填。sources 每项含 session_id、turn_id，支持跨轮证据。record_status（`ready` / `needs_review`）仅表示记录质量。

session_time 为标准时间或 null，另存原始值；time_expression 保留原文或 null；event_time 为事件日期/时间或 null，记录精度和推导依据，不补造日期或时区。

查询有效性为 `effective`、`historical`、`conflict`、`uncertain`、`irrelevant`，须附理由，不改写 Memory 为永久失效。关系 type 取四类标签；无法判断则记录 uncertain 及原因。

### 3.3 JSON 示例

课程 Caroline 示例，仅说明契约，不代表实际抽取结果：

```json
{
  "schema_version": "0.1",
  "dataset_version": "pending-course-confirmation",
  "memories": [
    {
      "memory_id": "conv26_D19_1",
      "conversation_id": "conv-26",
      "content": "Caroline passed the adoption agency interviews.",
      "entity": "Caroline",
      "attribute": "adoption_status",
      "value": "passed adoption agency interviews",
      "session_time": "2023-10-22T09:55:00",
      "time_expression": "last Friday",
      "event_time": null,
      "sources": [{"session_id": "19", "turn_id": "D19:1"}],
      "record_status": "ready"
    }
  ]
}
```

示例未推断日期或时区。导出须附来源数据或可定位来源的版本清单，记录抽取模型、提示词版本及构建配置。

## 4. 功能需求

下列 FR 均必做，按第 8 节验收。

| 编号 | 需求与验收条件 |
|---|---|
| FR-01 数据导入 | 导入课程对话，保持原文、说话人、会话和轮次对应；校验必填项、格式及重复 ID，失败定位记录，不误报成功；重复导入不得重复写入。 |
| FR-02 记忆构建 | 从原始对话自动抽取人物、事件、时间和状态，满足第 3 节且可溯源；人工演示记忆不能替代抽取。 |
| FR-03 构建任务反馈 | 报告状态、成功/失败数和错误位置；部分完成须明示，重试不重复写入。 |
| FR-04 统一导出 | 按对话或全集导出 UTF-8 JSON，含 schema_version、记忆及数据/构建版本；可解析、引用完整、ID 唯一。 |
| FR-05 记忆浏览 | 按对话展示内容、实体、时间、来源，支持实体/关键词筛选、分页或分批加载；空结果有提示。 |
| FR-06 证据回溯 | 点击记忆或答案引用可查看全部原始轮次和会话；来源缺失须报错，不用其他轮次替代。 |
| FR-07 问题输入 | 接收 conversation_id、非空问题、可选截止时间和正整数 top_k；参数非法或数据未构建须明确报错。 |
| FR-08 自动检索 | 从指定对话完整可用历史自动召回前 K 条，返回 ID、排序分数和来源；不足 K 条如实返回，不用 gold 预选候选。 |
| FR-09 关系判定 | 按第 5 节输出适用的四类关系、端点、理由和证据；不对不同实体或无关属性强建替代关系。 |
| FR-10 有效性解析 | 结合问题、时间与关系输出逐条有效性、理由、有效及冲突集合；保留历史来源，不删除原始记忆。 |
| FR-11 回答生成 | 基于解析结果回答并引用 Memory；证据不足返回 insufficient_evidence，影响结论的未决冲突返回 unresolved_conflict 并说明分歧，不表述为确定事实。 |
| FR-12 解析展示 | Web 展示问题、实际截止、候选、关系、理由、有效/历史/冲突状态、答案与证据，以及加载和错误；可用列表或时间线，不强制图数据库。 |
| FR-13 评测执行 | 批量运行 Full Text、Vector RAG 和本方法，保存逐题预测、证据、关系、错误、配置及汇总指标；gold 仅用于评分。 |

## 5. 状态与时间业务规则

### 5.1 关系判定

| 编号 | 规则 |
|---|---|
| BR-01 | 先检查实体、属性/事件、时间和查询语义是否可比，新事实不必然替代旧事实。 |
| BR-02 | RETAIN 表示相关事实兼容且无更新/替代依据；单条候选可直接标 effective，不制造双节点关系。 |
| BR-03 | UPDATE 表示同一过程阶段推进，如 researching → applied → passed interviews；当前取适用时间内的新阶段，保留历史，方向旧 → 新。 |
| BR-04 | SUPERSEDE 表示同一查询范围的新状态替代旧状态，方向旧 → 新。Gina 失业→开网店仅用于当前职业/业务查询，不推断其从未失业或所有职业互斥。 |
| BR-05 | CONFLICT 表示同一语义、重叠时间内事实互斥且无消解依据；不同时间的事实不因此冲突。关系对称，去重输出。 |
| BR-06 | 不能仅凭来源较晚认定新陈述为真，须有事件时间或语义依据；无法消解则标 conflict/uncertain，保留双方证据。 |
| BR-07 | 关系循环、引用缺失或解析矛盾均报告未决，不任意选取确定答案。 |

### 5.2 时间语义

- **BR-08 默认当前**：“当前”指所选对话可用历史的末端，不能使用运行机器日期替代对话时间；结果应显示实际截止条件。
- **BR-09 历史截止**：显式截止时间限制可使用的来源会话；晚于截止的陈述不得进入检索、推理或答案。语义性历史问题须结合事件时间解析，若无法可靠确定时间范围则返回澄清/不确定提示。该保守约定用于避免未来信息泄漏。
- **BR-10 事件与记录分离**：会话时间表示何时被陈述，事件时间表示何时发生。无法解析相对时间时保留原文和 null，不以记录时间伪装事件时间。
- **BR-11 历史有效性**：被更新的记忆仍可能是较早时间点的有效证据；不同查询不得互相污染有效性结果。
- **BR-12 无证据**：无候选或候选均不支持答案时，返回明确的证据不足状态；不得使用模型外部知识补成对话事实。

复杂时间推理为 Bonus，但默认截止、基本日期比较、历史保留及不确定时间处理属于必做正确性边界。

## 6. 主要用例

### UC-01 导入并构建

数据人员；前置：合法数据文件、可用构建配置。

1. 提交数据并选择记录的数据版本及划分。
2. 系统校验输入、保留原始来源并创建构建任务。
3. 系统逐批抽取、校验和保存 Memory，报告进度。
4. 用户浏览结果并导出 JSON。

后置：成功项可溯源、失败有记录。格式错误终止对应导入；模型失败标部分失败并可重试，不能冒充完整结果。

### UC-02 浏览和核查证据

演示用户；前置：对话已构建。

选择对话、筛选记忆、打开详情，查看全部来源原文和时间。空结果提示调整条件，来源损坏报定位错误；浏览不改原始记录或查询状态。

### UC-03 查询并解析

演示用户；前置：有可检索记忆。

1. 选择对话，输入问题、可选截止时间和 K。
2. 系统校验输入，依据时间范围从完整记忆集合检索。
3. 系统判定适用关系并计算查询级有效性。
4. 系统基于有效证据回答，返回引用和状态。
5. 用户检查候选、更新链、未决冲突和原始证据。

保存可核查结果。空问题拒绝执行，无证据明示，冲突展示双方；服务失败返回 request_id 和阶段，不生成伪答案。

### UC-04 批量评测

评测人员；前置：划分冻结，标注和配置可用。

按同一配置运行三方法，保存逐题输出后加载 gold 评分，汇总指标和错误。失败题不剔除；缺标注则记录不可评分及原因。

## 7. 接口与非功能需求

### 7.1 外部接口契约

本节规定逻辑接口；HTTP 路由见设计文档。

| 操作 | 输入 | 输出 |
|---|---|---|
| 导入 / 构建 | 数据文件、版本、划分、配置 | task_id、状态、校验错误 |
| 查询任务 | task_id | 阶段、进度、成功/失败数、错误摘要 |
| 列出记忆 | conversation_id、筛选、分页 | 记忆列表、总数、分页信息 |
| 证据详情 | Memory ID / 来源联合 ID | 记忆、原文、会话与轮次 |
| 导出 | 对话范围、schema 版本 | JSON 文件及版本信息 |
| 问答 | conversation_id、question、可选 as_of、top_k | 第 3.2 节 QueryResult |
| 批量评测 | 划分、方法、配置 | run_id、逐题输出、指标、失败统计 |

错误含 `code`、`message`、`request_id`，区分校验、数据缺失、模型不可用和超时。模型配置记录 provider/model、超时、提示词版本和参数；API Key 仅服务端读取。

### 7.2 非功能需求

| 编号 | 要求与验证方式 |
|---|---|
| NFR-01 可运行性 | 提供依赖、配置示例、数据获取和启动说明，另一成员可完成 UC-02/03；凭据缺失须提示。 |
| NFR-02 可追溯性 | 输出引用可定位原始轮次，验收样例失效引用为 0。 |
| NFR-03 可靠性 | 外部调用有限超时、有限重试，记录失败阶段；秒数和次数随配置冻结。 |
| NFR-04 可复现性 | 保存代码/数据版本、模型、提示词、K、随机参数及原始预测；外部模型不保证逐字复现，差异须可追踪。 |
| NFR-05 安全性 | 密钥不进入仓库、浏览器或日志；对话按不可信输入处理，不能借其指令泄密或覆盖规则；页面安全渲染文本。 |
| NFR-06 交互性能 | 拟定：单用户、本地已构建 6 段数据，列表/详情请求连续 20 次 P95 ≤2 秒；不计首次构建及外部模型调用，记录硬件、数据量、缓存条件。 |
| NFR-07 状态反馈 | 拟定：操作后 1 秒内显示状态；模型调用显示等待，超时明确失败。问答记录 P50/P95，阈值待选定模型后评审。 |
| NFR-08 可维护性 | 导入、抽取、检索、解析、生成、评测边界明确；框架/模型可配置，不硬编码课程答案。 |

NFR-06/07 为待评审目标，并非实测结果。

### 8.2 指标定义

**QA F1**：优先用课程评分程序。未提供时，按规范化后的 token 多重集合交集计分：P=交集数/预测 token 数，R=交集数/参考 token 数，F1=2PR/(P+R)，无交集为 0；多参考取最高分，逐题宏平均。暂定小写、去英文标点及冠词、合并空白；tokenizer、空答案及不可回答题规则随脚本冻结。课程规则到位后统一替换并重跑。

**证据 Recall@K**：暂按来源轮次比较，G 为 gold 证据集合，R 为前 K 条 Memory 的来源轮次并集，Recall@K=|G∩R|/|G|。K 指 Memory 数，轮次须含对话/会话 ID 并去重；暂报 K=5、10。G 为空时单列不可评分题数，不记为 1；课程若按 Memory 评分，须建立基于来源的确定映射。

**状态判断准确率**：优先按课程关系实例计，Accuracy=完全匹配数/可评分 gold 实例数。漏端点或关系均算错，不只统计已召回项；UPDATE/SUPERSEDE 检查方向，CONFLICT/RETAIN 按对称关系规范化。课程若合并更新/替代则显式映射，另报多余关系数量。标注单位和 Memory 映射待确认。

失败/超时计入总题数及失败率，有 gold 时记零分；缺 gold 的不可评分题单列。

### 8.3 基线与实验公平性

| 方法 | 输入与行为 |
|---|---|
| Full Text | 同一对话、时间范围的完整原始历史，无检索或状态解析 |
| Vector RAG | 共用本方法的记忆、向量检索及 K，候选直接用于生成 |
| 本方法 | 相同候选检索配置，增加关系与有效性解析 |

三方法共用问题集及尽可能一致的生成模型/参数。Full Text 超上下文限制须披露处理，不静默截断；其 Recall@K 为 N/A，未输出关系的基线状态准确率为 N/A。

“优于基线”是待验证假设，课程未给绝对分数门槛。报告均值、有效样本数、失败数、逐题输出、失败案例及相对基线变化。
