# 系统设计文档（M4 中期）

> 对应 M4 里程碑的「设计」部分，记录智能体动态记忆管理系统的总体架构、数据模型、模块划分与关键设计决策。
> 编码实现与测试结果见 [M4 功能测试报告](../testing/M4-功能测试报告.md)；需求依据见 [M3 SRS](../../PROJECT-MILESTONE3-第六组-SRE小组.md)。

## 1. 设计目标与原则

- **闭环可演示**：打通「导入 → 构建 → 浏览/溯源 → 检索 → 状态解析 → 问答/导出」六项必做。
- **可复现**：不依赖外部模型 / 向量库，评测与演示结果可重复。
- **可追溯**：每条记忆保留来源证据（会话 + 轮次）与时间信息，支持逐条有效性判定。

## 3. 数据模型（逻辑契约）

逻辑契约由 `backend/app/models.py` 定义（对应 SRS 3.1 / 3.2）。

### 3.1 记忆条目（Memory）

| 字段 | 类型 | 说明 |
|---|---|---|
| `memory_id` | str | 记忆唯一标识 |
| `conversation_id` | str | 所属会话 |
| `content` | str | 记忆内容（非空，空白校验） |
| `entity` / `attribute` / `value` | str? | 结构化三元组，可空、不猜测填充 |
| `session_time` | str? | 来源会话解析时间，未知为 null |
| `time_expression` | str? | 原始时间表达（如 "last Friday"），保留原文 |
| `event_time` | str? | 规范化事件时间，无法解析为 null（BR-10：不伪装） |
| `sources` | list[SourceRef] | 证据来源（`session_id` + `turn_id`，联合定位） |
| `record_status` | `ready` / `needs_review` | 记录状态 |

### 3.2 关系与状态类型

| 类型 | 取值 | 说明 |
|---|---|---|
| `RelationType` | `RETAIN` / `UPDATE` / `SUPERSEDE` / `CONFLICT` | 新旧记忆关系，方向统一旧 → 新 |
| `ValidityStatus` | `effective` / `historical` / `conflict` / `uncertain` / `irrelevant` | 查询级有效性五态 |
| `AnswerStatus` | `answered` / `insufficient_evidence` / `unresolved_conflict` | 答案状态 |
| `ResolutionMethod` | `turn_order` / `source_authority` / `evidence_count` / `none` | 冲突消解依据 |

> 关键约定：查询级有效性（`CandidateValidity`）与冲突消解（`ConflictResolution`）**不回写原始 Memory**，保证记忆可追溯、不被单次查询污染。

### 3.3 问答结果（QueryResult）

包含 `query_id / conversation_id / question / 时间条件 / candidates / relations / validity / resolution / answer`，覆盖检索、判定、消解、回答全链路，供前端分步展示。

## 6. 核心流程

### 6.1 导入与构建
读取 `data/raw` 的 LoCoMo demo-2conv（38 会话 / 788 轮 / 304 QA）→ 幂等导入 → 按对话构建记忆条目并关联来源轮次。

### 6.2 检索
查询文本经 TF-IDF 向量化，与记忆库计算相似度 → 按会话隔离 + Top-K 召回候选（返回 ID、排序分数与来源）。

### 6.3 状态解析
对候选记忆两两跑规则关系判定（RETAIN / UPDATE / SUPERSEDE / CONFLICT）→ 逐条有效性（effective / historical / conflict / uncertain / irrelevant）→ 冲突消解（按 turn_order / source_authority / evidence_count）。

### 6.4 问答与导出
基于「当前有效」记忆组装回答并附引用；支持 `as_of` 历史时间截止；导出 187 条记忆为统一 JSON，全带来源。

## 8. 关键设计决策

| 决策 | 理由 |
|---|---|
| 检索用 TF-IDF（sklearn `TfidfVectorizer`） | 轻量、无向量库 / 模型下载依赖，评测可复现 |
| 状态判定用规则 + mock LLM | 规避外部 API 不可复现；基线对照统一用规则模式 |
| 查询级有效性不回写原始 Memory | 保证记忆可追溯，符合 SRS 3.2 契约 |
| 记忆带来源证据 + 时间三字段 | 支撑溯源、`as_of` 历史视角与逐条有效性 |
| 导出带 `schema_version 0.1` | 便于版本化与验收核对 |

## 9. 已知局限与演进方向

- TF-IDF 对语义近义、词序 / 语法 / 否定、词形 / 拼写 / 缩写不鲁棒 → M5 换向量召回 + 查询扩展。
- 批量评测（F1 / Recall@K / 状态准确率）尚未落地 → M5 实现 FR-13 / AT-16。
- CONFLICT 消解为规则版，仅合成受控用例验证 → M5 结合图记忆与真实数据深化。
